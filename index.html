Cấu trúc dữ liệu và giải thuật

Tìm hiểu kỹ thuật chọn pivot Median-of-Three trong QuickSort

Khảo sát ảnh hưởng của Median-of-Three đến độ cân bằng phân hoạch và số phép so sánh, so với cách chọn pivot đầu mảng.

01 — Đặt vấn đề

Pivot ở hai đầu mảng

QuickSort chia mảng thành hai phần dựa trên pivot, rồi tiếp tục sắp xếp từng phần. Nếu pivot là giá trị nhỏ nhất hoặc lớn nhất, một phía sẽ rỗng còn phía kia chứa gần như toàn bộ mảng. Điều này dễ xảy ra khi luôn chọn a[low] hoặc a[high] làm pivot.

Một số dạng dữ liệu bất lợi

  • Tăng dần \([1,2,3,4,5,6,7,8]\) Đầu nhỏ nhất, cuối lớn nhất.
  • Giảm dần \([8,7,6,5,4,3,2,1]\) Đầu lớn nhất, cuối nhỏ nhất.
  • Gần có thứ tự \([1,2,3,5,4,6,7,8]\) Hai đầu vẫn là cực trị.
  • Hỗn hợp, cực trị ở hai đầu \([8,7,3,4,6,5,2,1]\) Dãy chưa có thứ tự, nhưng hai đầu là cực trị.

Với dãy tăng dần, chọn pivot đầu \(1\) khiến một phía có \(0\) phần tử, phía còn lại có \(7\). Chọn pivot cuối \(8\) cũng cho cách chia lệch như vậy. Điều này còn có thể xảy ra ở một mảng chưa có thứ tự:

\(\displaystyle A=\left[8,\,7,\,3,\,4,\,6,\,5,\,2,\,1\right].\)

Nếu mỗi lần phân hoạch chỉ loại được một phần tử, các lần gọi đệ quy sẽ xét những mảng có kích thước \(n-1,n-2,\ldots\). Khi đó:

\(\displaystyle T(n)=T(n-1)+\Theta(n)=\Theta(n^2).\)

Ngược lại, khi hai phía liên tục gần cân bằng, chi phí là \(\Theta(n\log n)\). Vì vậy, thay vì tìm trung vị của toàn mảng, có thể chọn pivot từ một số ít phần tử đại diện.

Mô phỏng giữ nguyên thứ tự đầu vào để so sánh riêng cách chọn pivot. Bản QuickSort gốc của Princeton có bước StdRandom.shuffle(a) nhằm tránh phụ thuộc vào thứ tự ban đầu; vì vậy, chọn pivot đầu không mặc nhiên kém trên mọi dữ liệu.

02 — Phương pháp

Median-of-Three

Median-of-Three xét ba phần tử ở đầu, giữa và cuối mảng con, rồi chọn giá trị đứng giữa trong ba giá trị đó (không phải trung bình cộng). Chỉ số giữa được tính bằng:

\(\displaystyle \mathrm{mid}=\mathrm{low}+\left\lfloor\dfrac{\mathrm{high}-\mathrm{low}}{2}\right\rfloor.\)

Hoán đổi để đưa pivot được chọn về đầu mảng (a[low]); hàm partition() không thay đổi.

Chọn trung vị của ba mẫu cần \(2\)–\(3\) phép so sánh. Vì chỉ xét ba phần tử, phương pháp này không bảo đảm tìm được trung vị của cả mảng hoặc luôn chia mảng cân bằng.

03 — Cài đặt Java

Cùng cách phân hoạch, khác cách chọn pivot

Hàm partition() luôn dùng a[low] làm pivot và đưa nó về đúng vị trí sau khi phân hoạch. Vì thế, hai chiến lược chỉ khác nhau ở bước chọn phần tử nào sẽ được đưa về a[low] trước khi gọi hàm này. Mã được điều chỉnh từ cách phân hoạch hai con trỏ của Sedgewick–Wayne sang int[].

Phân hoạch quanh a[low]

private static int partition(int[] a, int low, int high) {
    int i = low, j = high + 1;
    while (true) {
        while (a[++i] < a[low])
            if (i == high) break;

        while (a[low] < a[--j])
            if (j == low) break;

        if (i >= j) break;
        exch(a, i, j);
    }
    exch(a, low, j);
    return j;
}

Chọn pivot trong sort()

private static void sort(int[] a, int low, int high,
                         Strategy strategy) {
    if (high <= low) return;

    int pivotIndex = low;
    if (strategy == Strategy.MEDIAN_OF_THREE
            && high - low >= 2) {
        int mid = low + (high - low) / 2;
        pivotIndex = medianOf3(a, low, mid, high);
    }

    if (pivotIndex != low) exch(a, low, pivotIndex);
    int j = partition(a, low, high);
    sort(a, low, j - 1, strategy);
    sort(a, j + 1, high, strategy);
}
Xem cách cài đặt medianOf3() 
private static int medianOf3(int[] a, int i, int j, int k) {
    if (a[i] < a[j]) {
        if (a[j] < a[k]) return j;
        return a[i] < a[k] ? k : i;
    }
    if (a[i] < a[k]) return i;
    return a[j] < a[k] ? k : j;
}

05 — Phân tích và kết luận

Lợi ích khi xét nhiều đầu vào

Mô phỏng chỉ cho biết kết quả trên một mảng cụ thể. Để so sánh hai cách chọn pivot trên nhiều đầu vào, xét các mảng có giá trị không trùng nhau, trong đó mọi thứ tự xuất hiện đều có xác suất như nhau.

Gọi \(X\) là tỉ lệ phần tử nhỏ hơn pivot. Khi \(X\) gần \(0\) hoặc \(1\), hai phía rất lệch; khi \(X\) gần \(\dfrac{1}{2}\), chúng gần cân bằng. Với mảng đủ lớn, hai cách chọn pivot có mật độ của \(X\) lần lượt là:

\(\displaystyle f_1(x)=1,\qquad f_3(x)=6x(1-x),\qquad 0\lt x\lt 1. \)

Ở mô hình này, ba vị trí đầu, giữa và cuối tương ứng với ba mẫu ngẫu nhiên. Vì \(f_3(x)\) tập trung quanh \(x=\dfrac{1}{2}\), Median-of-Three có xu hướng chọn pivot chia mảng cân bằng hơn.

Để chuyển sự khác biệt về cách chia mảng thành số phép so sánh kỳ vọng, dùng hàm:

\(\displaystyle h(x)=-x\ln x-(1-x)\ln(1-x). \)

Hàm \(h(x)\) đạt giá trị lớn nhất khi \(x=\dfrac{1}{2}\). Với \(C_n\) là tổng số phép so sánh để sắp xếp \(n\) phần tử, khi \(n\) lớn ta có \(\mathbb E[C_n]\sim cn\ln n\). Hệ số \(c\) được xác định bởi:

\(\displaystyle c=\dfrac{1}{\mathbb E[h(X)]}. \)

Thay lần lượt \(f_1\) và \(f_3\) vào biểu thức kỳ vọng cho:

\(\displaystyle \begin{aligned} \text{Một mẫu:}\quad& \mathbb E[h(X)]=\dfrac{1}{2} &&\Longrightarrow c=2,\\[3pt] \text{Ba mẫu:}\quad& \mathbb E[h(X)]=\dfrac{7}{12} &&\Longrightarrow c=\dfrac{12}{7}. \end{aligned} \)
Chi tiết tính các giá trị kỳ vọng

Từ mật độ \(f(x)\), tính kỳ vọng của \(h(X)\) bằng:

\(\displaystyle \mathbb E[h(X)]=\int_0^1 f(x)\,h(x)\,\mathrm dx. \)

Pivot đầu (\(f_1(x)=1\)):

\(\displaystyle \mathbb E[h(X)]=\int_0^1 h(x)\,\mathrm dx=\dfrac{1}{2}. \)

Median-of-Three (\(f_3(x)=6x(1-x)\)), dùng tính đối xứng:

\(\displaystyle \begin{aligned} \mathbb E[h(X)] &=-12\int_0^1 x^2(1-x)\ln x\,\mathrm dx\\ &=-12\left(-\dfrac{1}{9}+\dfrac{1}{16}\right)\\ &=\dfrac{7}{12}. \end{aligned} \)

Trong phép tính trên, sử dụng:

\(\displaystyle \int_0^1 x^k\ln x\,\mathrm dx=-\dfrac{1}{(k+1)^2},\qquad k>-1. \)

So sánh hai hệ số \(2\) và \(\dfrac{12}{7}\), mức giảm lý thuyết là:

\(\displaystyle 1-\dfrac{12}{7}\cdot\dfrac{1}{2}=\dfrac{1}{7}\approx 14{,}29\%. \)

Số lần chọn pivot không vượt quá \(O(n)\), nên việc so sánh thêm \(2\)–\(3\) giá trị mỗi lần chỉ bổ sung \(O(n)\) phép so sánh. Vì vậy, chi phí này không làm thay đổi hệ số dẫn đầu của \(n\ln n\); số hoán đổi và thời gian chạy thực tế vẫn có thể tăng.

Phân tích trên giả sử các giá trị khác nhau. Nếu mảng có nhiều giá trị trùng lặp, cần xem xét thêm cách phân hoạch ba chiều thay vì chỉ thay cách chọn pivot.

Kết luận

Median-of-Three chọn pivot từ ba phần tử thay vì lấy cố định phần tử đầu. Với đầu vào ngẫu nhiên gồm các giá trị khác nhau, cách chọn này thường chia mảng cân bằng hơn và giảm khoảng \(14{,}29\%\) hệ số dẫn đầu của số phép so sánh kỳ vọng khi mảng lớn.

Để chọn pivot, thuật toán phải thực hiện thêm một vài phép so sánh. Số lần hoán đổi và thời gian chạy thực tế không nhất thiết giảm; trường hợp xấu nhất vẫn là \(\Theta(n^2)\).
