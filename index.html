Median-of-Three trong QuickSort

Một thay đổi nhỏ trong cách chọn pivot có thể giảm đáng kể chi phí phân hoạch. Vấn đề là: lợi ích ấy có đủ lớn để bù cho chi phí chọn pivot hay không?

\(01\) — Đặt vấn đề

Chọn pivot cố định có gì bất lợi?

QuickSort chọn một phần tử làm pivot, phân hoạch mảng rồi đệ quy trên hai mảng con. Nếu pivot nằm gần đầu hoặc cuối của thứ tự giá trị, việc phân hoạch có thể rất mất cân bằng.

Xét mảng chưa sắp xếp với \(8\) phần tử:

\(\displaystyle A=\left[8,\,7,\,3,\,4,\,6,\,5,\,2,\,1\right].\)

Nếu lấy a[lo] làm pivot, giá trị được chọn là \(8\) — phần tử lớn nhất. Sau lần phân hoạch đầu tiên, hai mảng con có kích thước \(7\) và \(0\).

Một lần phân hoạch lệch chưa đủ kết luận toàn bộ thuật toán có độ phức tạp bậc hai. Nhưng nếu liên tục xảy ra tại mỗi cấp, ta có:

\(\displaystyle T(n)=T(n-1)+\Theta(n)=\Theta(n^2).\)

Nếu phân hoạch gần cân bằng qua các cấp, độ phức tạp là \(\Theta(n\log n)\). Vì vậy, câu hỏi đặt ra là: có thể chọn pivot tốt hơn với chi phí đủ thấp không?

Ví dụ được chọn để minh họa, không đại diện cho mọi hoán vị ngẫu nhiên. QuickSort gốc Princeton sử dụng StdRandom.shuffle(a); mô phỏng này cố ý giữ nguyên đầu vào để thấy rõ ảnh hưởng của lựa chọn pivot.

\(02\) — Phương pháp

Median-of-Three hoạt động thế nào?

Ta lấy ba ứng viên tại lo, mid và hi, với:

\(\displaystyle \mathrm{mid}=\mathrm{lo}+\left\lfloor\dfrac{\mathrm{hi}-\mathrm{lo}}{2}\right\rfloor.\)

Chọn trung vị theo giá trị rồi đưa nó về lo để sử dụng hàm partition() ban đầu.

Trong ví dụ này, Median-of-Three giảm số phép so sánh từ \(39\) xuống \(27\), nhưng số hoán đổi tăng từ \(3\) lên \(7\). Vì vậy, cần phân biệt chi phí so sánh với thời gian chạy thực tế.

Median-of-Three lấy trung vị (median), không phải trung bình cộng (mean). Nó không bảo đảm tìm được trung vị của toàn bộ mảng hoặc loại trừ trường hợp xấu nhất.

\(03\) — Cài đặt Java

Giữ nguyên partition()

Mã dưới đây dựa trên phân hoạch hai con trỏ của Sedgewick–Wayne: i quét từ trái, j từ phải. Hai phiên bản giữ nguyên partition(); Median-of-Three chỉ thay đổi bước chọn pivot.

Phân hoạch hai con trỏ

private static int partition(int[] a, int lo, int hi) {
    int i = lo, j = hi + 1;
    while (true) {
        while (a[++i] < a[lo])
            if (i == hi) break;

        while (a[lo] < a[--j])
            if (j == lo) break;

        if (i >= j) break;
        exch(a, i, j);
    }
    exch(a, lo, j);
    return j;
}

Thay đổi cách chọn pivot

private static void sort(int[] a, int lo, int hi,
                         Strategy strategy) {
    if (hi <= lo) return;

    if (strategy == Strategy.MEDIAN_OF_THREE
            && hi - lo >= 2) {
        int mid = lo + (hi - lo) / 2;
        int median = medianOf3(a, lo, mid, hi);
        exch(a, lo, median);
    }
    int j = partition(a, lo, hi);
    sort(a, lo, j - 1, strategy);
    sort(a, j + 1, hi, strategy);
}
Xem cách cài đặt medianOf3() 
private static int medianOf3(int[] a, int i, int j, int k) {
    if (a[i] < a[j]) {
        if (a[j] < a[k]) return j;
        return a[i] < a[k] ? k : i;
    }
    if (a[i] < a[k]) return i;
    return a[j] < a[k] ? k : j;
}

\(05\) — Phân tích và kết luận

Lợi ích có bù được chi phí chọn pivot?

Xét mô hình các khóa phân biệt, mọi hoán vị đầu vào có xác suất như nhau. Khi \(n\) lớn, vị trí tương đối \(X\) của pivot được chọn ngẫu nhiên có mật độ \(f_1(x)=1\). Nếu lấy trung vị của ba mẫu ngẫu nhiên, mật độ trở thành \(f_3(x)=6x(1-x)\), tập trung nhiều hơn gần \(x=\dfrac{1}{2}\).

\(\displaystyle f_1(x)=1,\qquad f_3(x)=6x(1-x),\qquad 0\lt x\lt 1. \)

Với một hoán vị ngẫu nhiên, ba vị trí cố định đầu/giữa/cuối cũng tương ứng với ba mẫu ngẫu nhiên; điều này không đúng với đầu vào tùy ý.

Đặt hàm đo độ cân bằng của hai nhánh:

\(\displaystyle h(x)=-x\ln x-(1-x)\ln(1-x). \)

Với chi phí phân hoạch tiệm cận \(n\), số phép so sánh kỳ vọng có dạng \(\mathbb E[C_n]\sim cn\ln n\), trong đó:

\(\displaystyle c=\dfrac{1}{\mathbb E[h(X)]}. \)

Thay hai phân bố pivot vào công thức:

\(\displaystyle \begin{aligned} \text{Một mẫu:}\quad& \mathbb E[h(X)]=\dfrac{1}{2} &&\Longrightarrow c=2,\\[3pt] \text{Ba mẫu:}\quad& \mathbb E[h(X)]=\dfrac{7}{12} &&\Longrightarrow c=\dfrac{12}{7}. \end{aligned} \)
Chi tiết phép tính kỳ vọng

Với mật độ xác suất \(f(x)\), ta tính:

\(\displaystyle \mathbb E[h(X)]=\int_0^1 f(x)\,h(x)\,\mathrm dx. \)

Đối với một mẫu:

\(\displaystyle \mathbb E[h(X)]=\int_0^1 h(x)\,\mathrm dx=\dfrac{1}{2}. \)

Đối với trung vị ba mẫu, dùng tính đối xứng:

\(\displaystyle \begin{aligned} \mathbb E[h(X)] &=-12\int_0^1 x^2(1-x)\ln x\,\mathrm dx\\ &=-12\left(-\dfrac{1}{9}+\dfrac{1}{16}\right)\\ &=\dfrac{7}{12}. \end{aligned} \)

Ở đây sử dụng hệ thức:

\(\displaystyle \int_0^1 x^k\ln x\,\mathrm dx=-\dfrac{1}{(k+1)^2},\qquad k>-1. \)

Vì vậy \(c_1=2\) và \(c_3=\dfrac{12}{7}\).

Hệ số của số phép so sánh giảm:

\(\displaystyle 1-\dfrac{12}{7}\cdot\dfrac{1}{2}=\dfrac{1}{7}\approx 14{,}29\%. \)

Tìm trung vị ba mẫu cần \(2\)–\(3\) phép so sánh mỗi lần, với tối đa \(O(n)\) lần gọi; phần chi phí bổ sung là \(O(n)\), không thay đổi hệ số trước \(n\ln n\). Tuy nhiên, số hoán đổi có thể tăng nhẹ (theo slide \(28\)), và thời gian thực tế còn phụ thuộc dữ liệu, bộ nhớ cùng chi phí cài đặt.

Giới hạn: Median-of-Three vẫn có thể tạo phân hoạch lệch, vì thế không loại bỏ worst-case \(\Theta(n^2)\). Với nhiều khóa bằng nhau, kỹ thuật three-way partitioning thường thích hợp hơn; với mảng con nhỏ, có thể chuyển sang Insertion Sort.

Kết luận. Median-of-Three là một phương án cân bằng giữa chi phí chọn pivot thấp và chất lượng phân hoạch tốt hơn theo kỳ vọng; không phải một bảo đảm tăng tốc cho mọi đầu vào.
