Median-of-Three trong QuickSort

Một thay đổi nhỏ trong cách chọn pivot có thể giảm đáng kể chi phí phân hoạch. Vấn đề là: lợi ích ấy có đủ lớn để bù cho chi phí chọn pivot hay không?

01 — Đặt vấn đề

Chọn pivot cố định có gì bất lợi?

QuickSort chọn một phần tử làm pivot, phân hoạch mảng thành hai phía rồi tiếp tục đệ quy. Cách cài đặt đơn giản thường chọn phần tử đầu hoặc cuối. Cách này hầu như không mất chi phí lựa chọn, nhưng giá trị được chọn có thể là cực trị của mảng con.

Xét mảng [1, 2, 3, 4, 5, 6, 7]. Nếu luôn chọn phần tử đầu và không xáo trộn đầu vào, ta nhận được:

Ở mỗi cấp đệ quy, một phía gần như không giảm. Chi phí trong trường hợp này là T(n) = T(n−1) + Θ(n) = Θ(n²), trong khi phân hoạch cân bằng dẫn tới Θ(n log n). Như vậy, mục tiêu là giảm khả năng chọn pivot gây phân hoạch lệch.

Trong bản QuickSort gốc của Princeton, StdRandom.shuffle(a) được dùng trước khi sắp xếp để tạo tính ngẫu nhiên. Phân tích ở đây tách riêng ảnh hưởng của cách chọn pivot, nên ví dụ và mô phỏng không tự shuffle.

02 — Phương pháp

Median-of-Three hoạt động thế nào?

Thay vì chọn ngay a[lo], lấy ba ứng viên tại vị trí lo, mid = lo + (hi−lo)/2 và hi. Chọn trung vị theo giá trị trong ba ứng viên, rồi chuyển nó về lo để dùng thủ tục phân hoạch ban đầu.

Đối với mảng tăng dần ở trên, ba ứng viên là 1, 4, 7; chọn 4 sẽ tạo hai phần [1, 2, 3] và [5, 6, 7]. Việc tìm trung vị của ba mẫu chỉ cần 2–3 phép so sánh nếu dùng cây quyết định thích hợp.

Median-of-Three là median (trung vị), không phải mean (trung bình cộng). Nó cũng không phải trung vị của toàn bộ mảng.

03 — Cài đặt Java

Giữ nguyên partition()

Trong bài giảng Algorithms, Fourth Edition, Sedgewick và Wayne dùng phân hoạch hai con trỏ: i quét từ trái, j từ phải; các con trỏ dừng khi gặp phần tử bằng pivot. Median-of-Three chỉ bổ sung bước lựa chọn trước khi gọi cùng một hàm partition().

1. Phân hoạch hai con trỏ (mã gốc chuyển sang int[])

private static int partition(int[] a, int lo, int hi) {
    int i = lo, j = hi + 1;
    while (true) {
        while (a[++i] < a[lo])
            if (i == hi) break;

        while (a[lo] < a[--j])
            if (j == lo) break;

        if (i >= j) break;
        exch(a, i, j);
    }
    exch(a, lo, j);
    return j;
}

2. Thay đổi ở bước chọn pivot

private static void sort(int[] a, int lo, int hi,
                         Strategy strategy) {
    if (hi <= lo) return;

    if (strategy == Strategy.MEDIAN_OF_THREE
            && hi - lo >= 2) {
        int mid = lo + (hi - lo) / 2;
        int median = medianOf3(a, lo, mid, hi);
        exch(a, lo, median);
    }
    int j = partition(a, lo, hi);
    sort(a, lo, j - 1, strategy);
    sort(a, j + 1, hi, strategy);
}
Xem cách cài đặt medianOf3() 
private static int medianOf3(int[] a, int i, int j, int k) {
    if (a[i] < a[j]) {
        if (a[j] < a[k]) return j;
        return a[i] < a[k] ? k : i;
    }
    if (a[i] < a[k]) return i;
    return a[j] < a[k] ? k : j;
}

05 — Phân tích và kết luận

Lợi ích có bù được chi phí chọn pivot?

Xét mô hình các khóa phân biệt, mọi hoán vị đầu vào có xác suất như nhau. Trong giới hạn khi n lớn, tỉ lệ vị trí của một pivot chọn ngẫu nhiên có mật độ f₁(x) = 1. Nếu lấy trung vị của ba mẫu ngẫu nhiên phân biệt, mật độ trở thành f₃(x) = 6x(1−x): các vị trí gần giữa mảng được ưu tiên hơn. Với một hoán vị ngẫu nhiên, ba vị trí cố định đầu/giữa/cuối cũng tương ứng với ba mẫu ngẫu nhiên; điều này không đúng với đầu vào tùy ý.

Đặt h(x) = −x ln x − (1−x) ln(1−x).

Với chi phí mỗi phép phân hoạch tiệm cận n, hệ số dẫn đầu của E[Cₙ] ~ c n ln n là c = 1/E[h(X)].

Một mẫu: E[h(X)] = 1/2 ⇒ c = 2.

Ba mẫu: E[h(X)] = 7/12 ⇒ c = 12/7.

Chi tiết phép tính kỳ vọng

Hệ số trên xuất phát từ truy hồi kỳ vọng của hai nhánh sau phân hoạch. Với mật độ f(x), ta tính E[h(X)] = ∫₀¹ f(x)h(x)dx.

Với f₁(x)=1: E[h(X)]=1/2.

Với f₃(x)=6x(1−x) và tính đối xứng: E[h(X)] = −12∫₀¹ x²(1−x)ln(x)dx = 7/12.

Do ∫₀¹ xᵏ ln(x)dx = −1/(k+1)², tích phân phía trên bằng −7/144. Từ đó thu được c₁=2, c₃=12/7.

Hệ số của số phép so sánh giảm 1/7 ≈ 14,29%. Tìm trung vị ba mẫu cần 2–3 phép so sánh mỗi lần, với tối đa O(n) lần gọi; phần chi phí bổ sung là O(n), không thay đổi hệ số trước n ln n. Tuy nhiên, số hoán đổi có thể tăng nhẹ (theo slide 28), và thời gian thực tế còn phụ thuộc dữ liệu, bộ nhớ cùng chi phí cài đặt.

Giới hạn: Median-of-Three vẫn có thể tạo phân hoạch lệch, vì thế không loại bỏ worst-case Θ(n²). Với nhiều khóa bằng nhau, kỹ thuật three-way partitioning thường thích hợp hơn; với mảng con nhỏ, có thể chuyển sang Insertion Sort.

Kết luận. Median-of-Three là một phương án cân bằng giữa chi phí chọn pivot thấp và chất lượng phân hoạch tốt hơn theo kỳ vọng; không phải một bảo đảm tăng tốc cho mọi đầu vào.
