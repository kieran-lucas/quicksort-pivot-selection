Cấu trúc dữ liệu và giải thuật

Tối ưu QuickSort bằng Median-of-Three

Chọn pivot ảnh hưởng thế nào đến tốc độ QuickSort? Báo cáo tìm hiểu nguyên nhân, cách cải tiến và giới hạn của phương pháp — dựa trên mã Java trong Algorithms, 4th Edition.

01 / Đặt vấn đề

Pivot đầu mảng có thể làm QuickSort chậm

QuickSort chọn một phần tử làm pivot, phân hoạch mảng rồi đệ quy trên hai mảng con. Nếu luôn lấy phần tử đầu làm pivot, mảng đã tăng dần sẽ liên tục bị chia lệch: một phía rỗng, phía còn lại chỉ giảm một phần tử.

Ví dụ với A = [1, 2, 3, 4, 5, 6, 7]
Pivot đầu (1) [] | 1 | [2, 3, 4, 5, 6, 7] 0 : 6
Pivot giữa giá trị (4) [1, 2, 3] | 4 | [5, 6, 7] 3 : 3

Mỗi lần phân hoạch tốn Θ(n) thao tác. Nếu luôn lệch, tổng chi phí là Θ(n²); nếu cân bằng, tổng chi phí là Θ(n log n). Vì vậy, bài toán không nằm ở việc pivot lớn hay nhỏ, mà ở độ cân bằng của hai mảng con.

Câu hỏi: Có cách chọn pivot tốt hơn mà không làm chi phí lựa chọn quá lớn không?

02 / Giải pháp

Median-of-Three

Chọn ba ứng viên: phần tử đầu a[lo], giữa a[mid] và cuối a[hi], với mid = lo + (hi - lo)/2. Pivot là giá trị trung vị trong ba ứng viên — không phải trung bình cộng.

Ví dụ
Mảng[8, 1, 6, 4, 9, 2, 7]
Ba ứng viên8 (đầu), 4 (giữa), 7 (cuối)
Trung vị4 < 7 < 8 → pivot = 7

Chỉ cần đưa trung vị về đầu mảng rồi dùng lại partition() gốc. Kỹ thuật giúp tránh các pivot cực trị trong ba mẫu, nhưng không bảo đảm pivot gần trung vị thật của cả mảng.

03 / Cài đặt

Triển khai Java

Mã dưới đây dựa trên 2-way partition của Sedgewick–Wayne (trang 13 và 28). Để đối chiếu công bằng, hai phiên bản dùng cùng thuật toán phân hoạch; thay đổi duy nhất là bước chọn pivot. Mã dùng int[] thay cho Comparable[] trong slide.

Phân hoạch gốc

JAVA / two-way partition
private static int partition(int[] a, int lo, int hi) {
    int i = lo, j = hi + 1;

    while (true) {
        while (a[++i] < a[lo])
            if (i == hi) break;

        while (a[lo] < a[--j])
            if (j == lo) break;

        if (i >= j) break;
        exch(a, i, j);
    }

    exch(a, lo, j);
    return j;
}

Bổ sung Median-of-Three

JAVA / median-of-three
private static void sort(int[] a, int lo, int hi,
                         Strategy strategy) {
    if (hi <= lo) return;

    if (strategy == Strategy.MEDIAN_OF_THREE) {
        int mid = lo + (hi - lo) / 2;
        int median = medianOf3(a, lo, mid, hi);
        exch(a, lo, median);
    }

    int j = partition(a, lo, hi);
    sort(a, lo, j - 1, strategy);
    sort(a, j + 1, hi, strategy);
}

private static int medianOf3(int[] a, int i, int j, int k) {
    if (a[i] < a[j]) {
        if (a[j] < a[k]) return j;
        return a[i] < a[k] ? k : i;
    }
    if (a[i] < a[k]) return i;
    return a[j] < a[k] ? k : j;
}

04 / Minh họa

Chạy thử trên cùng một mảng

05 / Đánh giá

Hiệu quả và giới hạn

Với các khóa phân biệt và mô hình hoán vị ngẫu nhiên đều, vị trí tương đối của pivot lấy từ một mẫu có mật độ tiệm cận f₁(x)=1. Trung vị của ba mẫu ngẫu nhiên có mật độ f₃(x)=6x(1−x), tập trung hơn quanh x=1/2, nơi phân hoạch cân bằng nhất.

Chỉ tiêu tiệm cậnMột mẫuMedian-of-Three
So sánh kỳ vọng2n ln n(12/7)n ln n
Hoán đổi kỳ vọng(1/3)n ln n(12/35)n ln n
Worst-caseΘ(n²)Θ(n²)

Kết quả: hệ số dẫn đầu của số phép so sánh giảm 1 − (12/7)/2 = 1/7 ≈ 14,29%. Chi phí chọn trung vị là 2–3 phép so sánh mỗi lần chọn, tổng cộng bậc O(n); vì vậy không làm thay đổi hệ số trước n ln n. Đây là kết quả của mô hình lấy mẫu ngẫu nhiên, không phải cam kết tăng tốc 14,29% trên mọi máy hoặc mọi mảng.

Median-of-Three vẫn có thể gặp phân hoạch rất lệch và worst-case Θ(n²). Với nhiều giá trị trùng, nên dùng three-way partitioning; với mảng con nhỏ, có thể chuyển sang Insertion Sort (trang 27, 42–47).

Kết luận: Median-of-Three là sự đánh đổi giữa chi phí chọn pivot rất nhỏ và khả năng tạo ra phân hoạch tốt hơn; nó cải thiện hiệu năng kỳ vọng chứ không loại bỏ trường hợp xấu nhất.
