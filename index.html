Cấu trúc dữ liệu và giải thuật

Tìm hiểu kỹ thuật chọn pivot Median-of-Three trong QuickSort

Khảo sát ảnh hưởng của Median-of-Three đến độ cân bằng phân hoạch và số phép so sánh, so với cách chọn pivot đầu mảng.

01 — Đặt vấn đề

Pivot ở hai đầu mảng

Trong QuickSort, giá trị pivot ảnh hưởng trực tiếp đến kích thước hai mảng con. Chọn a[low] hoặc a[high] làm pivot rất đơn giản, nhưng dễ tạo phân hoạch lệch nếu phần tử được chọn là giá trị nhỏ nhất hoặc lớn nhất.

Một số dạng dữ liệu bất lợi

  • Tăng dần \([1,2,3,4,5,6,7,8]\) Đầu nhỏ nhất, cuối lớn nhất.
  • Giảm dần \([8,7,6,5,4,3,2,1]\) Đầu lớn nhất, cuối nhỏ nhất.
  • Gần có thứ tự \([1,2,3,5,4,6,7,8]\) Hai đầu vẫn là cực trị.
  • Hỗn hợp, cực trị ở hai đầu \([8,7,3,4,6,5,2,1]\) Dãy chưa có thứ tự, nhưng hai đầu là cực trị.

Với dãy tăng dần, pivot đầu \(1\) tạo phân hoạch \(0:7\), còn pivot cuối \(8\) tạo \(7:0\). Ngay cả mảng chưa được sắp xếp cũng có thể gặp tình trạng này:

\(\displaystyle A=\left[8,\,7,\,3,\,4,\,6,\,5,\,2,\,1\right].\)

Nếu sự mất cân bằng lặp lại ở mọi cấp, chi phí của QuickSort thỏa mãn:

\(\displaystyle T(n)=T(n-1)+\Theta(n)=\Theta(n^2).\)

Khi các phân hoạch được duy trì gần cân bằng, QuickSort có độ phức tạp \(\Theta(n\log n)\). Vì vậy, cần cải thiện cách chọn pivot mà không tăng đáng kể chi phí.

Các ví dụ trên không đại diện cho mọi đầu vào. Với hoán vị ngẫu nhiên, pivot đầu không mặc nhiên xấu. Phiên bản Princeton có bước StdRandom.shuffle(a); mô phỏng ở đây giữ nguyên thứ tự đầu vào.

02 — Phương pháp

Median-of-Three

Lấy các giá trị tại ba vị trí low, mid và high, rồi chọn trung vị của chúng làm pivot:

\(\displaystyle \mathrm{mid}=\mathrm{low}+\left\lfloor\dfrac{\mathrm{high}-\mathrm{low}}{2}\right\rfloor.\)

Đưa pivot được chọn về vị trí a[low] bằng phép hoán đổi; hàm partition() không thay đổi.

Tìm trung vị ba mẫu cần \(2\)–\(3\) phép so sánh. Đây không phải trung vị của toàn mảng; Median-of-Three vẫn có thể tạo phân hoạch lệch.

03 — Cài đặt Java

Giữ nguyên partition()

Cả hai phiên bản dùng phân hoạch hai con trỏ của Sedgewick–Wayne (chuyển sang int[]). Khác biệt nằm ở bước chọn pivot trước khi gọi partition().

Phân hoạch hai con trỏ

private static int partition(int[] a, int low, int high) {
    int i = low, j = high + 1;
    while (true) {
        while (a[++i] < a[low])
            if (i == high) break;

        while (a[low] < a[--j])
            if (j == low) break;

        if (i >= j) break;
        exch(a, i, j);
    }
    exch(a, low, j);
    return j;
}

Thay đổi cách chọn pivot

private static void sort(int[] a, int low, int high,
                         Strategy strategy) {
    if (high <= low) return;

    int pivotIndex = low;
    if (strategy == Strategy.MEDIAN_OF_THREE
            && high - low >= 2) {
        int mid = low + (high - low) / 2;
        pivotIndex = medianOf3(a, low, mid, high);
    }

    if (pivotIndex != low) exch(a, low, pivotIndex);
    int j = partition(a, low, high);
    sort(a, low, j - 1, strategy);
    sort(a, j + 1, high, strategy);
}
Xem cách cài đặt medianOf3() 
private static int medianOf3(int[] a, int i, int j, int k) {
    if (a[i] < a[j]) {
        if (a[j] < a[k]) return j;
        return a[i] < a[k] ? k : i;
    }
    if (a[i] < a[k]) return i;
    return a[j] < a[k] ? k : j;
}

05 — Phân tích và kết luận

Chi phí và hiệu quả kỳ vọng

Giả sử các giá trị trong mảng không trùng nhau và mọi hoán vị đầu vào có xác suất như nhau. Với \(n\) lớn, vị trí chuẩn hóa \(X\) của pivot đầu có mật độ \(f_1(x)=1\); trung vị ba mẫu có mật độ \(f_3(x)=6x(1-x)\), tập trung hơn quanh \(x=\dfrac{1}{2}\).

\(\displaystyle f_1(x)=1,\qquad f_3(x)=6x(1-x),\qquad 0\lt x\lt 1. \)

Trong mô hình hoán vị ngẫu nhiên, ba vị trí đầu, giữa và cuối cũng cho ba giá trị lấy mẫu ngẫu nhiên; điều này không đúng với mọi mảng đầu vào.

Để biểu diễn mức độ cân bằng của hai nhánh, đặt:

\(\displaystyle h(x)=-x\ln x-(1-x)\ln(1-x). \)

Khi chi phí mỗi lần phân hoạch xấp xỉ số phần tử đang xét, \(\mathbb E[C_n]\sim cn\ln n\), trong đó:

\(\displaystyle c=\dfrac{1}{\mathbb E[h(X)]}. \)

Lấy kỳ vọng theo hai phân bố trên:

\(\displaystyle \begin{aligned} \text{Một mẫu:}\quad& \mathbb E[h(X)]=\dfrac{1}{2} &&\Longrightarrow c=2,\\[3pt] \text{Ba mẫu:}\quad& \mathbb E[h(X)]=\dfrac{7}{12} &&\Longrightarrow c=\dfrac{12}{7}. \end{aligned} \)
Phép tính kỳ vọng

Với mật độ \(f(x)\):

\(\displaystyle \mathbb E[h(X)]=\int_0^1 f(x)\,h(x)\,\mathrm dx. \)

Một mẫu:

\(\displaystyle \mathbb E[h(X)]=\int_0^1 h(x)\,\mathrm dx=\dfrac{1}{2}. \)

Trung vị ba mẫu, sử dụng tính đối xứng:

\(\displaystyle \begin{aligned} \mathbb E[h(X)] &=-12\int_0^1 x^2(1-x)\ln x\,\mathrm dx\\ &=-12\left(-\dfrac{1}{9}+\dfrac{1}{16}\right)\\ &=\dfrac{7}{12}. \end{aligned} \)

Với hệ thức:

\(\displaystyle \int_0^1 x^k\ln x\,\mathrm dx=-\dfrac{1}{(k+1)^2},\qquad k>-1. \)

Mức giảm của hệ số dẫn đầu:

\(\displaystyle 1-\dfrac{12}{7}\cdot\dfrac{1}{2}=\dfrac{1}{7}\approx 14{,}29\%. \)

Số lần chọn pivot là \(O(n)\), nên chi phí lấy ba mẫu chỉ bổ sung \(O(n)\) phép so sánh và không làm thay đổi hệ số của \(n\ln n\). Số hoán đổi và thời gian chạy thực tế không nhất thiết giảm.

Với nhiều giá trị bằng nhau, phân hoạch ba chiều phù hợp hơn; với mảng con nhỏ có thể dùng Insertion Sort.

Kết luận

Với mảng có các giá trị không trùng nhau và thứ tự ban đầu ngẫu nhiên, Median-of-Three thường tạo phân hoạch cân bằng hơn. Khi kích thước mảng lớn, hệ số dẫn đầu của số phép so sánh kỳ vọng giảm khoảng \(14{,}29\%\) so với chọn pivot đầu mảng.

Để chọn pivot, thuật toán phải thực hiện thêm một vài phép so sánh. Số lần hoán đổi và thời gian chạy thực tế không nhất thiết giảm; trường hợp xấu nhất vẫn là \(\Theta(n^2)\).
